M7 live map: measured runs, 2026-09-29
======================================

1. WebSocket traffic on the recorded one-hour live session
----------------------------------------------------------
Input: the one-hour BarentsWatch Live AIS recording of 2026-09-29
(127,893 records, 13:39-14:39 UTC), replayed by msgtime:

  mt-ingest --replay norway-live-2026-09-29.jsonl --format barentswatch \
            --speed N --serve 18090 --listening-since 1790689162

A standard-library Python client connected once and recorded every message
for 30 seconds of wall clock. Sizes are WebSocket payload bytes (JSON).

At real time (speed 1) a browser receives one update a second of about
11 KB; a newly connected browser first gets the whole picture (128 KB for
2,489 vessels). At 60x, each one-second update carries a minute of data, so
most vessels have moved and updates approach snapshot size.

2. Docker image, built and checked from outside
-----------------------------------------------
  docker build -t maritime-tracker .
  docker run -d --name mt -p 18080:8080 maritime-tracker
  tools/check_live_map.py http://127.0.0.1:18080/ --min-tracks 50 --updates 3

The container replays the bundled 5,000-record sample in real time. This
build ran on a network behind a TLS-inspecting proxy, so it used
--build-arg BASE=<ubuntu:24.04 plus that proxy's CA certificate>; the CI
docker job builds with the default base.
